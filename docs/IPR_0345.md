# IPR responsiveness — 0.3.45

Studied upstream RenderGui::updateProgressiveRendering and snapshotFrame:
https://github.com/OpenMoonRay/moonray_gui/blob/main/cmd/moonray_gui_v2/RenderGui.cc

The upstream viewer uses PROGRESSIVE / PROGRESSIVE_FAST modes, checks display readiness and film activity, throttles snapshots by FPS, and waits for a displayed snapshot before starting the next changed frame. Its pixel display does not wait for final file output.

This plugin update reduces scene-change polling from 1200 to 150 ms and settings debounce from 400 to 150 ms. External asset checks remain limited to once per second. Mouse drags still update only after release.

Optional “Refine when idle (16 SPP)” starts one 16-SPP uniform pass 750 ms after a quick IPR pass completes. It reuses the configured capture and persistent renderer where available, retains the existing displayed image, and keeps the selected resolution. Pending scene edits take priority. It does not reuse the quick pass's sample accumulation. It is off by default to preserve the requested one-sample behavior. Denoising stays disabled, and final settings are unchanged.

Remaining native work: our persistent runtime still uses BATCH scheduling with 250 ms snapshot requests and writes completed outputs. Adopting native progressive scheduling, readiness-aware snapshots and completion without EXR round trips needs a separately built runtime and validation. This update does not claim those changes or measured speedups.

Validation: syntax inspection only; tests/test_ipr.py prepared but not run. Deferred manual checks: IPR on/off, release after object drag, settings coalescing, stop/close during refinement, locked preview, edits immediately before refinement, final render unaffected, and observed time to first pixels.
